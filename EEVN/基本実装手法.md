# 基本実装手法 (EEVN - React Native / Expo 版)

## 1. 使用ライブラリ・環境構成と実装パターン

### 1.1 Node.js / npm・Expo 環境
* **Node.js / npm**: システム環境との競合を避け、ユーザー空間 `/home/jiro/.local/node/bin`（`v26.13.1` / `npm 11.20.0`）を先頭 `PATH` に設定して実行する。
* **日本語（マルチバイト）パス環境での Android Gradle ビルド**:
  * 本リポジトリの親ディレクトリ `/home/jiro/デスクトップ/EVV/EEVN` には日本語文字列が含まれるため、Android Gradle / CMake / AGP ツールチェーンが文字化け・異常終了する場合がある。
  * **対策**: `npx expo prebuild` 完了後、`EEVN` を `/tmp/eevn_ascii`（ASCII のみのパス）へ同期コピーし、`/tmp/eevn_ascii/android` 配下で `./gradlew :app:assembleDebug` を実行する。

### 1.2 主要パッケージと実用法
* **`expo-sqlite`**: `SQLite.openDatabaseAsync('bookshelf.db')` / `openDatabaseSync` による同期・非同期クエリとトランザクション管理（`withExclusiveTransactionAsync` / 逐次キュー）。
* **`@react-native-async-storage/async-storage`**: JSON シリアライズによる設定永続化とアプリ内購読リスナーパターン（Explorer / Bookshelf / Viewer 間のリアルタイム設定共有）。
* **`expo-image`**: ローカルファイル URI（`file:///...`）からの高速非同期デコード・メモリキャッシュ表示（サムネイル＆フルスクリーン閲覧）。
* **極薄 Kotlin モジュール（`modules/eev-storage`）**:
  * React Native JS 層だけでは困難な `MANAGE_EXTERNAL_STORAGE` 権限処理と、ディレクトリ走査＋サムネイルJPEGリサイズ保存をネイティブ1往復で完了させることで JS ブリッジのボトルネックを排除する。

## 2. バグ防止の具体的ルール・注意点

### 2.1 例外ハンドリング（`try-catch` 必須ルール：絶対適用）
* ネイティブブリッジ呼び出し、SQLite 読み書き、AsyncStorage アクセス、ファイルパス操作、配列ソート、Android `BackHandler` 登録、ジェスチャハンドラのすべてに **`try-catch` を配置し、失敗時はログ出力＋安全値（`[]` / `null` / `false`）へフォールバック**して JS 例外やネイティブクラッシュによる強制終了を完全に防止する。

### 2.2 本棚未登録フォルダ削除の安全設計（データ消失防止）
* 削除対象は**現在表示中ディレクトリの直下フォルダ**のみに厳格限定し、通常ファイル（直下の画像・設定ファイルなど）は一切含めない。
* 対象フォルダが「お気に入りに登録されている」「直下にサブフォルダが1つ以上ある」「お気に入りフォルダパスが `<targetPath>/` で始まっている（子孫に本棚フォルダを持つ）」のいずれかに該当する場合は**必ず保護対象として除外**する。
* 削除前に件数とフォルダ名リストを確認ダイアログで提示し、明示承認後のみ実行する。

### 2.3 通常フォルダ＆本棚フォルダの 2段階即時ロード（Stale-While-Revalidate）
* フォルダを開いた瞬間に同期走査や全サムネイル生成を待つとスクロールや画面遷移が重くなるため、以下の2段階で行う：
  1. SQLite（`folder_cache.db` / `bookshelf.db`）から既存のメタデータと永続サムネイルパス（`filesDir/folder_thumbs` / `filesDir/bookshelf_thumbs`）を即座に読み出して描画。
  2. 裏側で実ディレクトリの `lastModified`・サムネイルファイル実在を確認し、差異があるフォルダのみ `EevStorage.getFolderMetadata()` をバッチ呼び出しして UI と DB を更新。

### 2.4 次期フェーズ（フェーズ2: OCR・翻訳再実装）に向けた注意点
* 既存 `EVV` アプリの実装方式は踏襲せず、`/home/jiro/デスクトップ/trans_image/docs` を参照して一から OCR・翻訳・テキストグループ化・DB 連携を設計・実装する。

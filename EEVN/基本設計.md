# 基本設計書 (EEVN - React Native / Expo 版)

## 1. システムアーキテクチャ設計

### 1.1 全体構成（UI/状態: React Native ＋ 極薄ネイティブ層: Kotlin）
本アプリは React Native（Expo Prebuild / TypeScript）を主軸とし、JS 層のみで実現困難または高速化が必要な OS 機能だけをローカル Expo Module（`modules/eev-storage`）の極薄 Kotlin コードに委譲する。

1. **Core 基盤層（`src/core/`）**: Feature モジュールに一切依存しない。共有モデル定義、AsyncStorage 設定永続化、`folder_cache.db` 管理、ソートユーティリティ、共通テーマ・戻る操作制御を提供する。
2. **Feature 機能層（`src/features/`）**: MVVM（React Custom Hooks による ViewModel パターン）を採用し、`Screen`（純粋UI）と `use*ViewModel`（状態・副作用）と専用 DB/ロジックを機能単位フォルダに凝集する。
3. **極薄 Kotlin ネイティブモジュール（`modules/eev-storage`）**:
   * Android 11+ `MANAGE_EXTERNAL_STORAGE` 権限判定と設定画面インテント起動
   * 外部ストレージ直下のファイル・サブフォルダ走査と更新日時取得
   * 画像メタ情報（画像枚数・先頭画像・`.trans_image.db` 有無・サブフォルダ有無）取得と、`filesDir/<thumbDirName>/<sha256>.jpg`（最大辺 256px JPEG）への永続サムネイル生成・個別/一括削除
   * 安全な再帰ファイル/フォルダ削除

### 1.2 アーキテクチャ区分と依存関係
* **Core / Feature 単方向依存ルール**: `Core` は `Feature` に依存せず、`Feature` は `Core` の公開 API と共有モデルのみを参照する。
* **1ファイルサイズ目安**: 約400行を上限とし、肥大化する前にサブモジュール・ダイアログ群を分離する。

## 2. 主要機能の設計詳細

### 2.1 通常フォルダの永続サムネイル保存・2段階即時表示
* **永続保存先**: `filesDir/folder_thumbs` に元パスの SHA-256 ハッシュ名（`.jpg`）で保存し、OS による `cacheDir` 自動消去を回避する。
* **SQLite キャッシュ（`folder_cache.db`）**: `folder_cache_items` テーブルに `folder_path (PK)`, `last_modified`, `image_count`, `thumb_path`, `has_trans_db`, `has_sub_dirs` を保持する。
* **2段階ロード手順（`useExplorerViewModel`）**:
  1. `listDirectory` でディレクトリ一覧を取得した直後、`FolderMetadataDb.getByPaths()` で既知フォルダのサムネイル・画像数・翻訳DBフラグを即座に UI へマージ表示する。
  2. バックグラウンドで「未キャッシュ」「`last_modified` 不一致」「サムネイルファイル欠損」のフォルダのみをバッチ単位で `EevStorage.getFolderMetadata()` へ渡し、UI・`folder_cache.db` を差分更新する。

### 2.2 本棚未登録フォルダの一括削除（サブフォルダを含まない）
* **抽出ロジック（`collectDeletableNonFavoriteFolders`）**:
  * 現在ディレクトリ直下の項目からディレクトリのみを抽出し、以下すべてを満たすものだけを候補に含める：
    1. お気に入り集合 `favoriteFolderPaths` に含まれない。
    2. 対象フォルダ直下にサブディレクトリが 0 件である（サブフォルダを含まない）。
    3. いずれのお気に入りフォルダパスも対象フォルダパスの子孫（`<targetPath>/...`）ではない。
  * 直下の通常ファイル（画像等）は一覧対象外として保護する。
* **確認とクリーンアップ**: 対象件数とフォルダ名リストを確認ダイアログで表示し、承認後に `deletePath` ＋ `deleteThumbnail('folder_thumbs')` ＋ `FolderMetadataDb.deleteByPaths()` を順次実行する。

### 2.3 本棚機能・カテゴリ管理・複数選択 AND 検索・カスタム順
* **SQLite DB（`bookshelf.db`）**:
  * `bookshelf_items`: `folder_path (PK)`, `folder_name`, `custom_order`, `thumb_path`, `image_count`, `last_modified`, `has_trans_db`
  * `bookshelf_categories`: `id (INTEGER PK AUTOINCREMENT)`, `name (TEXT UNIQUE)`, `created_at`
  * `bookshelf_folder_categories`: `folder_path`, `category_id`（複合主キー）
* **カテゴリ絞り込みロジック（AND検索）**:
  * `selectedCategoryIds.isEmpty()`（「すべて」）→ 全件
  * `selectedCategoryIds.contains(UNCATEGORIZED_CATEGORY_ID)`（「未分類」）→ `categoryIds.isEmpty()` のフォルダ
  * その他 → `selectedCategoryIds.every(id => folder.categoryIds.includes(id))`（AND条件）
* **カスタム順並べ替え**: `SortOrder.CUSTOM`（昇順）・`SortOrder.CUSTOM_DESC`（降順）を定義し、リスト/グリッド上でジェスチャ/操作によりアイテム順序を入れ替え可能とし、確定時に `updateCustomOrders()` で DB 保存する。

### 2.4 画像ビューワとフォルダ循環移動
* **漫画モード**: 見開き画像（横幅が高さ以上の画像も含む任意画像）を `expo-image`＋レイアウトクリップまたはサイズ計測により右半分（`RIGHT_HALF`）→ 左半分（`LEFT_HALF`）の順でクロップ表示する。
* **フォルダ移動（`ViewerDirectoryNavigator`）**:
  * 本棚起動時は本棚で現在絞り込まれている対象フォルダ集合を受け取り、`viewerSortOrder`（`CUSTOM` / `CUSTOM_DESC` 含む）でソートした上で、末尾↔先頭を循環移動する。

### 2.5 フェーズ2（OCR・翻訳再実装方針）
* 次期フェーズでは `/home/jiro/デスクトップ/trans_image/docs` のアーキテクチャ・座標マッピング・DBスキーマ・ルビ復元仕様を精査し、既存コードに依存しない独立した新規モジュールとして再設計・実装する。

### 2.6 例外ハンドリング方針（ランタイムクラッシュ防止：絶対ルール）
* **try-catch 必須ルール**: ネイティブモジュール呼び出し、ファイルI/O、SQLite トランザクション・クエリ、AsyncStorage 読み書き、画像表示・寸法取得、ソート処理、UI ジェスチャおよび Android `BackHandler` など、**実行時エラーが発生しうるすべての処理を `try-catch` で捕捉し、アプリがクラッシュしないようにする**。
* **フォールバック方針**: 例外発生時は `console.warn` / `console.error`（ネイティブ側は `android.util.Log`）で記録し、空配列・デフォルト値・`false`・前状態維持のいずれかへフォールバックして処理を継続する。
